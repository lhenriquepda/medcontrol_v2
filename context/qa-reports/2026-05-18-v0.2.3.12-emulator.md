## 4. NEW bugs discovered

### NB-1 (P2) — Treatment cache stale after non-mutation insert
**Where:** `src/hooks/useTreatments.js:14-15`
**Severity:** P2 (data freshness)
**Description:** `useTreatments({patientId})` has `staleTime: 30 * 60_000` AND `refetchOnMount: false`. If a treatment is inserted via a non-mutation path (e.g., direct API call, another device, Realtime subscription failure, or RPC bypass), the patient detail page can show "Sem tratamentos ativos" for up to 30min even after reloading the page. Reload does NOT force refetch.
**Repro:** Insert treatment via SQL RPC → reload patient detail page → 0 active treatments rendered even though 9 doses from that treatment ARE visible (doses query has different staleTime).
**Recommendation:** Either set `refetchOnMount: 'always'` for `useTreatments` OR rely on Realtime postgres_changes invalidation (verify Realtime is actually working for `treatments` table for the logged-in user).

### NB-2 (P3) — Persistent toast after action completes
**Where:** Share/Unshare toast UX
**Severity:** P3 (cosmetic)
**Description:** Green "Paciente compartilhado com teste-free@teste.com" toast remained visible while user performed unshare action on same dialog. User sees stale success toast for an action they just reversed.
**Recommendation:** Clear toasts on dialog interaction OR shorten toast duration to <3s.

### NB-3 (P2) — In-app update install error spam
**Where:** Google Play Core API integration
**Severity:** P2 (log spam, no user impact)
**Description:** Logcat shows `-6: Install Error(-6): The download/install is not allowed, due to the current device state` repeating dozens of times in normal session.
**Cause:** Google Play in-app update API failing on emulator (which has no Play Store install ability).
**Recommendation:** Gate `InAppUpdate` polling: skip on emulator or skip when offline / when error -6 / when last error <10min ago. Currently spamming Sentry breadcrumbs needlessly.

### NB-4 (P1) — Loss of mark on rapid app kill (Flow 1B)
**Where:** `confirmDose` mutation queue flush timing
**Severity:** P1 (data loss on adverse OS)
**Description:** If user marks a dose and the app is force-killed within ~500ms-1s (OS battery saver, user swipe, low-mem kill), the optimistic UI shows "tomada" but mutation never reached IDB persist → on next launch, dose shows pending again on server.
**Recommendation:** Either:
1. Make confirmDose persistImmediately to IDB BEFORE returning from onMutate (flush mutation cache synchronously)
2. Add a "last action timestamp" + sync-status indicator in UI so user knows the mark may not have synced if they back-out fast.

### NB-5 (P3) — Onboarding LS version key mismatch
**Where:** `OnboardingTour.jsx:9` and `cdp_skip_onboarding.mjs`
**Severity:** P3 (dev tool only)
**Description:** `__APP_VERSION__` returns `null` at runtime in production build (Vite define plugin appears to substitute build-time but emulator probe showed `appV: null`). This means the onboarding could potentially re-trigger on every version change for users, OR not trigger when expected. Worth verifying define plugin output.

### NB-6 (P3) — `versionName` mismatch on stale APK
**Where:** Build pipeline
**Severity:** P3 (dev hygiene)
**Description:** First gradle `assembleDebug` was run before `npm run build:android`, resulting in APK with version code 75 but assets/version.json showing 0.2.3.11. After rebuild with sync, mismatch resolved. **Recommendation:** Make `assembleDebug` depend on cap sync OR add a guard that fails build if version mismatch detected.

## 9. Recommended fix priority

### Top 5 to fix in current release v0.2.3.12:

1. **NB-4 (P1) — Mark dose persistence on rapid kill** — Critical UX bug; if user kills app fast, dose disappears. Solution: persistImmediately on onMutate, OR show a "syncing" indicator until mutation completes.

2. **NB-1 (P2) — Treatment cache stale 30min** — Set `useTreatments` to `refetchOnMount: 'always'` for patient detail page OR ensure Realtime subscription on `treatments` is reliable. This currently makes cross-device usage unreliable.

3. **NB-3 (P2) — In-app update install error spam** — Gate Play Core update calls when offline, on emulator (debug build), or after error -6. Currently filling logcat + Sentry.

4. **Audit Bug #2 (P2) — `_optimistic` flag in confirmDose** — Add `_optimistic: true` to dose patch (per pattern in createPatient/updatePatient at `src/services/mutationRegistry.js:298-300`), so a UI sync indicator can be rendered. Pairs with fix for NB-4.

5. **NB-2 (P3) — Stale toast on share/unshare** — Trivial UX polish.

### Defer to next release:

- **Flow 10 token refresh stall** — needs long-idle test session
- **Audit Bug #5 unshare timeout** — not reproducible in current network conditions
- **Audit Bug #9 multi-dose desync** — not reproducible with rapid marking
- **NB-5 `__APP_VERSION__` undefined** — verify Vite define configuration
- **NB-6 versionName mismatch** — build-time hygiene
