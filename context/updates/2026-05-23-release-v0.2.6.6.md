# Release v0.2.6.6 — 2026-05-23 (vc 91)

> Bug crônico **"perde comunicação com BD após idle"** finalmente resolvido.
> Diagnóstico via 4 agentes paralelos (Supabase client + mutation flow + native lifecycle + DB schema) — todos convergiram pra mesma cadeia causal.

## Bug #0023 (P0 crônico) — FIXED

**Sintoma user (relatos repetidos há meses):**
> "O app as vezes, principalmente quando fica aberto um tempo sem interação, ele não grava as informações, não consigo cadastrar SOS, tratamento, ele meio que perde a comunicação com o BD"

**Root cause confirmado (4 agentes + postgres_log prod):**
```
[1] App idle 30-60min (Doze mode Android)
[2] JWT Supabase expira (default 3600s)
[3] WebView pausada → processLock supabase-js órfão mid-refresh
[4] App volta → useAppResume.onResume tenta refreshSession
    Se falha transient (Doze, lock contention) → catch swallows error
    qc.refetchQueries NUNCA executa, qc.resumePausedMutations NÃO chamado
    onlineManager pode estar sticky false
[5] User clica "SOS" → RPC com JWT stale → auth.uid()=NULL
[6] RPC v2 retorna JSONB {ok:false, error:'unauthorized', code:401} HTTP 200
    (NÃO usa RAISE EXCEPTION → supabase-js não detecta como erro)
[7] mutationRegistry.onError faz rollback + Sentry log (sample 1%)
    NÃO mostra TOAST UI
[8] User: optimistic update reverteu silenciosamente → "perdeu BD"
```

**Evidência empírica:** Postgres logs prod últimas 24h confirmaram `permission denied for table doses/patients` recorrente.

## 8 Fixes aplicados

### F1 — Re-sync onlineManager pós-resume
**Arquivo:** `src/hooks/useAppResume.js`
Capacitor Network listener pode morrer junto com WebView durante Doze. Pós-resume, re-query `Network.getStatus()` + `onlineManager.setOnline()`. Cura sticky-false que pausava mutations 'offlineFirst'.

### F2 — resumePausedMutations() pós-soft-recover
**Arquivo:** `src/hooks/useAppResume.js`
Antes só rodava no boot hydrate. Mutations persistidas no IDB durante idle ficavam dormentes. Agora drena pós-resume.

### F3 — Watchdog ping pós-resume
**Arquivo:** `src/hooks/useAppResume.js`
Ping leve `user_prefs.select` com timeout 5s. Token "renovado" pode estar zombie (processLock corrompido). Se 401 ou timeout → signOut+reload (único caso onde reload é OK — client supabase-js estruturalmente quebrado).

### F4 — rpcV2WithAuthRetry wrapper
**Arquivo:** `src/services/dosesService.js`
Detecta unauthorized/401 → `refreshSession()` + retry 1× antes de propagar. Cura cenário "user clica após idle, falha mas refresh recupera". Wraps confirmDose/skipDose/undoDose.

### F5 — Mutation Error Bus + Listener
**Arquivos:** `src/state/mutationErrorBus.js` (NEW), `src/components/MutationErrorListener.jsx` (NEW), `src/services/mutationRegistry.js`
Event bus pra toast UI quando mutation falha (não-409). Antes onError fazia só rollback silent + Sentry — user via otimista reverter sem entender. Agora toast user-friendly:
- "Sessão expirou. Faça login novamente."
- "Falha de conexão ao registrar SOS. Sua mudança ficará pendente."
- "Sem permissão para criar tratamento."
Cobre TODAS mutations (8 handlers): registerSos, create/updatePatient, create/update/pause/resume/endTreatment, plus handleDoseMutationError.

### F7 — DROP overloads RPC stale
**Migration:** `supabase/migrations/20260523180000_v0_2_6_6_drop_rpc_overloads.sql`
PostgREST escolhia overload errado quando cliente omitia params opcionais → mutation usava versão sem proteções RLS atuais. Dropped:
- `register_sos_dose`: 3 overloads (5/6/8 params) → 1
- `create_treatment_with_doses`: 2 (11/13) → 1
- `extend_continuous_treatments`: 2 (1/2) → 1
- `share_patient_by_email`: 3 (2/3/4) → 1
- `confirm_dose/skip_dose/undo_dose` v1 deprecated (v2 em uso desde v0.2.6.1)

Resultado: TODAS RPCs com 1 overload única (zero ambiguidade).

### F8 — Sentry visibilidade total 401/403/409
**Arquivo:** `src/main.jsx` beforeSend
Eventos críticos de auth healthcare pulam rate-limit (10/dia) + fingerprint sample (1% repetições). Cobre "bug raro mas crítico que dilui em ruído". Permite detectar precoce em prod.

### Skipped F6
DoseModal usa `.mutate()` fire-and-forget — F5 já cobre via event bus, não silencia mais.
