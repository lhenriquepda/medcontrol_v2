# Release v0.2.6.3 — 2026-05-23 (vc 88 mandatory)

> **Hotfix #2** sobre v0.2.6.2 vc 87 (que era hotfix de v0.2.6.1 vc 85).
> User testou v0.2.6.2 em prod e reportou 3 problemas estruturais novos:
> 1. Histórico de Doses ainda não mostra antibióticos do Rael (cache stale)
> 2. Autofill sempre sugerindo "Antidepressivo" (sticky state)
> 3. Falta cruzar texto digitado com BD CMED em tempo real + mostrar origem

## Bugs FIXED

### #0015 — Cache TanStack stale persistente em IDB

**Sintoma:** Mesmo após DOSE_COLS + RPC fix em v0.2.6.2, alguns users (com APK atualizado de versões antigas) ainda viam "Outro" no Histórico/Analytics.

**Root cause:** PersistQueryClientProvider usa key `dosy-query-cache` no IDB com buster `v1`. Payloads serializados pré-fix (de vc 84/85) ainda têm doses sem `group_id`. TanStack hydrate carrega esse cache stale na 1ª abertura da nova versão, user vê dados velhos até cache expirar (gcTime 24h).

**Fix:** Bump buster `v1` → `v2` em `main.jsx` (PersistQueryClientProvider) + `mutationRegistry.js` (flushPersistImmediate). Force purge único do IDB local na 1ª abertura do novo APK. Próximo fetch bate no server e popula com group_id presente.

**Trade-off:** pico egress global aceito (1× por user). Sem isso, user fica preso em cache stale até gcTime.

### #0016 — Autofill sticky "sempre Antidepressivo"

**Sintoma:** User digita "Escitalopram" (→ antidepressivo), apaga, digita "Amoxil". UI continua mostrando "Antidepressivo" como categoria.

**Root cause:** useEffect em `TreatmentForm.jsx` e `SOS.jsx` aplicava `classifyResult.group_id` somente quando `form.group_id` era NULL (early return se já populado). Quando user troca o medName, classifyResult vem com novo group_id mas useEffect não atualiza (form.group_id stale).

Plus: hook `useClassifyMedication` só rodava quando `!form.group_id` — bloqueava re-classificação ao mudar medName.

**Fix:**
- `useClassifyMedication(medName)` sempre roda (sem condicional)
- useEffect re-aplica classifyResult em TODA mudança via dep `[classifyResult, medName]`
- Distingue **manual pick** (`autoFilledGroup=false`) de **autofill** (`autoFilledGroup=true`)
- Se autoFilled E novo classifyResult.group_id → atualiza form
- Se autoFilled E classifyResult null → LIMPA form.group_id (evita stale)
- Se manual pick → respeita escolha do user (never overwrites)

### #0017 — Falta cruzar BD CMED real-time + origem no dropdown

**Sintoma:** Sugestões aparecem mas não tem badge indicando se vem do CMED ANVISA, do histórico do user, ou de heurística. Hook `useClassifyMedication` chamava RPC `classify_medication_robust` que **não existia** no DB.

**Root cause:** RPC `classify_medication_robust` foi documentada em v0.2.4.0 mas nunca criada. Hook sempre caía no fallback heurístico cliente-side, que tem regex amplo demais.

**Fix:** Migration `v0_2_6_3_classify_medication_robust_5tier` cria RPC 5-tier server-side:

| Tier | Lookup | Confidence | source |
|---|---|---|---|
| 1 | DCB exact (Denominação Comum Brasileira) | 1.0 | `dcb` |
| 2 | Catalog nome_comercial exact | 0.95 | `catalog_exact` |
| 3 | Catalog nome LIKE prefix match | 0.85 | `catalog_like` |
| 4 | Principio_ativo LIKE | 0.75 | `principio_like` |
| 5 | Heurística sufixo farmacológico server-side | 0.55 | `heuristic_suffix` |

Tier 5 REFINADO com regex word-boundary aware (era `/pram|alina/` muito ampla → capturava palavras genéricas). Cobertura por 14 classes terapêuticas.

Smoke tests pass: Amoxil/Cefaclor/Bactrim/Sulfatrim/Clavulin → antibiotico; Aerolin/Berotec/Symbicort → broncodilatador; Escitalopram (DCB) → antidepressivo; Losartana → anti_hipertensivo; XYZ random → null (cliente abre CategoryHintModal).

**MedNameInput dropdown badges:**
- `DCB ANVISA` (azul) — Denominação Comum Brasileira
- `CMED` (verde) — nome comercial registrado catálogo ANVISA
- `SEU` (laranja peach) — histórico do usuário
- (texto livre sem match) → sem badge
