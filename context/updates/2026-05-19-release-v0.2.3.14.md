## Fixes implementados (3 bugs P2 + empilhamento C)

### #0010 — banner version_name correto

`src/hooks/useAppUpdate.js` — inverte ordem de resolução de versão:
1. DB autoritativa (`app_releases.name`) primeiro
2. Play Core `info.availableVersion` apenas se shape semver (`/\d+\.\d+/`)
3. Fallback `versão N` (sem `v` prefix pra evitar `"vversão 77"`)

**Why:** plugin `@capawesome/capacitor-app-update` retorna `availableVersion = "77"` (versionCode stringified) quando Play Store backend ainda não populou versionName imediatamente pós-publish. `??` truthy curto-circuitava DB lookup.

### #0011 — modal mandatory robusto a race `currentVersionCode=null`

`src/hooks/useAppUpdate.js` — query upper-bound-only quando currentVc null:

```js
let mandQuery = supabase.from('app_releases')
  .select('version_code')
  .lte('version_code', availableVc)
  .eq('is_mandatory', true)
  .limit(1)
if (currentVc != null && currentVc < availableVc) mandQuery = mandQuery.gt('version_code', currentVc)
const { data: mandRows } = await mandQuery
mandatory = !!mandRows?.length
```

**Why:** race `useEffect getRealVersion` vs Play Core check → `currentVersionCode=null` no primeiro check pulava mandatory inteiro. Trade-off: falso-positivo possível em fresh install muito antigo. Aceitável em healthcare (erro pelo lado seguro).

### #0009 — share error UI com retry

`src/hooks/useShares.js` + `src/components/SharePatientSheet.jsx`:
- `useShares` retry handler skip auth errors (401/PGRST301 não retry)
- `SharePatientSheet` renderiza error state explícito + botão "Tentar novamente" quando query `['patient_shares', id]` em `status: 'error'`

**Why:** consumer só lia `isLoading` → 401 + sem retry deixava "Carregando..." infinito sem feedback ao user.

### Empilhamento C — debugability

- **Sentry breadcrumbs** em `fetchReleaseFromDb` (info path feliz / warning fallback path / error DB fail) — futura visibilidade de race Play Core em prod
- **Copy sanitization fallback** — banner sem duplo `v` em "versão N" e modal sem chip ugly `"VERSÃO versão N DISPONÍVEL"` em path fallback. Default semver path inalterado
- **Debug toggle** `window.__dosyForceFallback` pra testar copy fallback localmente sem precisar derrubar DB query

## Decisões

### DB autoritativa primeiro vs Play Core primeiro

Mantido princípio v0.2.3.11 (#299): DB é fonte da verdade. Bug #0010 reforçou: Play Core pode retornar stringified versionCode em vez de versionName real → confiar só quando shape semver. Trade-off: 1 extra query por session (DB lookup). Negligível.

### Mandatory falso-positivo em fresh install antigo

Aceito. Healthcare critical path — preferível user instalar versão atual do que ficar em build vulnerável. Modal mandatory tem botão "Atualizar agora" direto Play Store, custo de UX baixo.

### Debug toggle `__dosyForceFallback`

Window-level toggle (não env var). Permite testar copy fallback sem precisar derrubar DB query. Padrão consistente com `__dosyForceUpdate`/`__dosyForceMandatory` já existentes em v0.2.3.11.
