# Release v0.2.6.5 — 2026-05-23 (vc 90)

> User feedback session pós-shipping v0.2.6.4. Foco: UX mobile (teclado, PTR), AdMob banner display fix per-device, bug de sincronização Dashboard após mark-done.

## Bugs FIXED

### #0018 — Keyboard cobre input/textarea ao focar
- **Sintoma:** Em Android Capacitor WebView, ao tocar input/textarea/select, teclado virtual aparecia sobre o campo. User não via o que estava digitando. Bug recorrente em TODO lugar com input.
- **Fix:** Hook global `useKeyboardAwareScroll` instalado em `App.jsx`. Delegation de `focusin` em `document` + listener Capacitor `Keyboard.keyboardWillShow` (native only) chamam `scrollIntoView({block:'start', behavior:'smooth'})` com delay 220ms (tempo do teclado abrir).
- **Offset dinâmico:** CSS `scroll-margin-top` calc(env(safe-area-inset-top) + var(--ad-banner-height) + var(--update-banner-height) + var(--app-header-height) + 12px). Respeita pilha sticky atual sem hardcode.

### #0019 — AdMob banner desaparecia / ficava SOBRE status bar
- **Sintoma:** Banner Test Ad (`ca-app-pub-3940256099942544/6300978111`) não aparecia no emulator. Quando aparecia, ficava SOBRE a status bar (cobrindo battery/clock/notch).
- **Root cause duplo:**
  1. `initializeForTesting: !import.meta.env.PROD` — `vite build` SEMPRE seta PROD=true → `!PROD=false` → modo prod em test slot → Google retorna NO_FILL (errorCode 3). Banner silenciosamente falhava em build local.
  2. `margin: 0` no `showBanner` — AdMob plugin usa coordenadas ABSOLUTAS da tela (não relativas ao WebView, mesmo com overlay:false). Banner sobreposto à status bar.
- **Fix:**
  1. `const isUsingTestAd = ADMOB_BANNER_ANDROID === TEST_AD_UNIT` → `initializeForTesting: isUsingTestAd` + `testingDevices: ['EMULATOR']`. Garante test mode SEMPRE que usando test slot.
  2. Native Android `MainActivity.java`: `ViewCompat.setOnApplyWindowInsetsListener` mede `WindowInsetsCompat.Type.statusBars() + displayCutout()` (cobre notch/punch-hole), converte px → DP via density, injeta como `--system-status-bar-height` CSS var + `window.__dosySystemStatusBarHeight` JS var. `useAdMobBanner.js` lê esse valor + `waitForStatusBarHeight(500ms)` antes do showBanner. Per-device dinâmico — Pixel 8 punch-hole ~38dp, Samsung notch ~44dp, devices antigos 24dp.

### #0020 — Dashboard "X atrasadas" stale após marcar dose via MultiDoseModal
- **Sintoma:** Alarme dispara → user clica "Ciente" → MultiDoseModal abre → marca 2 doses como Tomadas → modal fecha → header alert badge SUMIU corretamente, mas Dashboard card "2 doses atrasadas" persiste + lista de doses ainda mostra elas como overdue.
- **Root cause:** `confirmDose/skipDose/undoDose/registerSos` `onMutate` fazia `cancelQueries({queryKey:['doses']})` mas NÃO cancelava `['dashboard-payload', *]` que é o que Dashboard usa. Query in-flight (refetch background) continuava rodando, retornava server data pre-mutation, TanStack `setQueryData` SOBRESCREVIA o cache patched com `_localActedAt` stamp perdido. Reconcile não tinha como proteger.
- **Header funcionou:** `HeaderAlertIcon` usa `useDoses(filter)` → queryKey `['doses', *]` → cancelada corretamente.
- **Fix:** Adicionar `cancelQueries({queryKey:['dashboard-payload']})` em paralelo com `cancelQueries({queryKey:['doses']})` em todas 4 mutations. Plus `refetchDoses()` em `onSettled` agora invalida ambos namespaces (consistência).

## Melhorias UX

### Pull-to-refresh expandido
- **Antes:** Só Dashboard tinha PTR. Outras páginas user precisava sair/voltar pra refresh.
- **Agora:** PTR adicionado em **Patients, PatientDetail, DoseHistory, Analytics**. Cada página define seu próprio `handleRefresh` que invalida queries relevantes.
- **Spinner overlay:** Antes ficava com `top: 0` → AdMob native overlay z-order acima do WebView → spinner invisível atrás do banner. Novo `<PullToRefreshOverlay>` componente reutilizável posiciona em `top: var(--ad-banner-height) + var(--update-banner-height)`.

### Categorias de input com `data-keyboard-scroll`
- Hook respeita `data-keyboard-scroll="false"` para opt-out
- Suporta opt-in extra com `data-keyboard-scroll="true"` para botões customizados que abrem sheets com search interno

## Infra dev (não afeta prod)

### LiveReload mode (opt-in via env)
- `capacitor.config.ts`: `process.env.DOSY_LIVERELOAD === '1'` ativa `server.url: http://10.0.2.2:5173` + `cleartext: true`. Sem env, config default unchanged.
- `network_security_config.xml`: domain-config pra `10.0.2.2` com `cleartextTrafficPermitted="true"` (IP privado emulator-only, não atinge real device). Resto do app mantém pinning + cleartext blocked.
- Uso: `DOSY_LIVERELOAD=1 npx cap sync android` + `npm run dev -- --host 0.0.0.0` + uma RUN no Android Studio → WebView fetcha de Vite dev server → hot reload sem RUNs subsequentes.
